# GitHub Actions Cloud APK Build

This project is designed for GitHub Actions cloud builds. The local machine is
used for editing and committing source code; APKs are built in GitHub Actions.

Do not commit `local.properties`, keystores, passwords, real nodes, subscription
URLs, UUIDs, or server information.

## Debug Workflow

Workflow file:

```text
.github/workflows/android-debug.yml
```

Triggers:

- Manual: GitHub repository -> Actions -> Android Debug Build -> Run workflow
- Automatic: push to `main`

Build command:

```bash
./gradlew :app:lintDebug --stacktrace
./gradlew :app:assembleDebug --stacktrace
```

Artifact:

```text
myproxy-debug-apk
```

Download path in the workflow run:

```text
Artifacts -> myproxy-debug-apk
```

## Release Workflow

Workflow file:

```text
.github/workflows/android-release.yml
```

Triggers:

- Manual: GitHub repository -> Actions -> Android Release Build -> Run workflow
- Automatic: push tag matching `v*`, for example `v1.0.0`

Build command:

```bash
./gradlew :app:testDebugUnitTest --stacktrace
./gradlew :app:lintDebug --stacktrace
./gradlew :app:assembleRelease --stacktrace
```

Artifact:

```text
myproxy-release-apk
```

Download path in the workflow run:

```text
Artifacts -> myproxy-release-apk
```

For a pushed `v*` tag, the workflow also creates a GitHub Release and attaches:

```text
MyProxy-<version>-android.apk
MyProxy-<version>-android.apk.sha256
```

A manual workflow run creates the Actions Artifact only; it does not publish a
versioned GitHub Release.

## Required GitHub Secrets

Add these repository secrets before running the Release workflow:

- `KEYSTORE_BASE64`
- `KEYSTORE_PASSWORD`
- `KEY_ALIAS`
- `KEY_PASSWORD`

The workflow decodes `KEYSTORE_BASE64` into a temporary file named
`release-keystore.jks` on the GitHub runner, then passes its path to Gradle as
`KEYSTORE_FILE`.

## Convert a Keystore to Base64

PowerShell:

```powershell
[Convert]::ToBase64String([IO.File]::ReadAllBytes("C:\path\to\release.jks")) | Set-Content -NoNewline "keystore-base64.txt"
```

macOS or Linux:

```bash
base64 -w 0 /path/to/release.jks > keystore-base64.txt
```

If `-w` is unsupported:

```bash
base64 /path/to/release.jks | tr -d '\n' > keystore-base64.txt
```

Copy the contents of `keystore-base64.txt` into the GitHub secret
`KEYSTORE_BASE64`, then delete the local text file.

## Artifact Installation

1. Open a successful workflow run.
2. Download the APK artifact.
3. Extract the downloaded zip.
4. Transfer the APK to the phone.
5. Install it. If Android blocks installation, allow the file manager or browser
   to install unknown apps, install the APK, then disable that permission again.

## Common Errors

`Release 签名环境变量缺失`

- One or more release signing secrets is missing.
- Check `KEYSTORE_BASE64`, `KEYSTORE_PASSWORD`, `KEY_ALIAS`, and `KEY_PASSWORD`.

`Release 签名文件不存在`

- The workflow did not decode `KEYSTORE_BASE64` into the expected file.
- Check the `Restore release keystore` step.

`Execution failed for task ':app:minifyReleaseWithR8'`

- Check `app/proguard-rules.pro`.
- Review missing class warnings and keep only real packages/classes.

`app/libs/libv2ray.aar` not found

- Ensure `app/libs/libv2ray.aar` is committed to the repository or
  downloaded/generated by the workflow.

`geoip.dat` or `geosite.dat` missing

- Ensure both files exist under `app/src/main/assets/`.

Debug builds fail after signing changes

- Debug builds should not require release signing secrets.
- Check that signing validation is attached only to Release tasks.
